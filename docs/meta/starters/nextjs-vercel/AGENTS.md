## Commands

```bash
npm run dev          # dev server (mock mode if MOCK=1)
npm run check        # lint + typecheck + tests — the pre-ship gate; CI runs the same
npm run build        # production build — catches RSC/route/boundary errors tests miss
```

## Workflow

- Work in a fresh worktree off `origin/main`; never commit to `main`
  (`scripts/setup-worktree.sh` installs a hook that refuses it).
- One task → one PR. Title starts with the work-item ID. PR body: scope statement, test plan.
- No drive-by fixes: unrelated improvements become filed issues, not commits.
- Name branches explicitly in every command: `gh pr create --head <branch> --base main`.
- Before opening a PR from a checkout with unrelated WIP: fresh worktree, copy in only your
  files, PR from there.
- Red PRs from prior agent runs are triage items — fix before starting new work.

## Framework

This repo runs the Next.js version in `package.json`, which may differ from your training
data. Before writing route handlers, middleware, metadata, server actions, or caching code,
read the installed docs: `node_modules/next/dist/docs/`. Do not assume remembered behavior.

## Memory

- `docs/solutions/` — grep before debugging anything that looks familiar.
- `docs/decisions/` — read the relevant ADR before changing a decided area.
- `docs/plans/` — write a plan there before multi-file work; plans are the scope of record.
- After a non-obvious fix: add a solutions entry in the same PR. If a rule would have
  prevented the problem, amend this file in the same PR.

## Never

- Flip feature flags, edit env/secrets, or run production migrations.
- Merge outside the policy in `docs/autonomy-runbook.md`.
- Touch payments/auth beyond the picked item's written spec.
