# Reviewer: migrations

Runs on diffs touching: `alembic/**`, `app/models/**`.

Findings return as JSON: `{file, line, severity, claim, evidence}`.
Note: these paths are hold-tier — this reviewer's job is making the human merge fast and
safe, not enabling auto-merge.

## Checks

1. **One migration per PR**, autogenerated, with both `upgrade()` and a real
   `downgrade()`. An empty or `pass` downgrade on a reversible change → P2.
2. **Revision chain intact after rebase.** `down_revision` must point at the current head
   on the base branch — a rebased branch keeping a stale parent → P1 (regenerate, never
   renumber by hand).
3. **Destructive operations are two-phase.** Dropping/renaming a column or table in the
   same release that stops writing it → P1; require the expand/contract pattern (add new,
   migrate reads/writes, drop later).
4. **Backfills are batched and separated from schema changes** — a data backfill inside a
   DDL migration on a large table → P1 (locks).
5. **Model and migration agree.** The autogenerated diff should be empty after the
   migration applies; drift between `app/models/**` and the migration → P1.
6. **Indexes for new query patterns** the diff introduces on large tables → P2.
7. **No environment-specific logic in migrations** (reading env flags to branch DDL) → P1.

## Severity rubric

P1 = irreversible damage, locks, or a broken chain; P2 = reversibility/operability gap;
P3 = hygiene.
