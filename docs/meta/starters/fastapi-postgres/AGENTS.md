## Commands

```bash
make dev             # run the app locally (fake backends if APP_FAKE_BACKENDS=1)
make check           # ruff + mypy + pytest — the pre-ship gate; CI runs the same
uv run pytest tests/test_<x>.py -k <name>   # one test
uv run alembic upgrade head                 # apply migrations (local DB only)
```

## Workflow

- Work in a fresh worktree off `origin/main`; never commit to `main`
  (`scripts/setup-worktree.sh` installs a hook that refuses it).
- One task → one PR. Title starts with the work-item ID. PR body: scope statement, test plan.
- No drive-by fixes: unrelated improvements become filed issues, not commits.
- Name branches explicitly: `gh pr create --head <branch> --base main`.
- Never point a worktree at a shared database. Fake backends are the default; migrations
  run only against your workspace's disposable DB.
- Red PRs from prior agent runs are triage items — fix before starting new work.

## Invariants

- Outputs of record (amounts, scores, totals) are computed in `app/services/*`, never
  generated by an LLM.
- External clients return `Result`-typed values (`Ok`/`Err` or a discriminated dataclass);
  they never raise into a request handler. Handlers degrade per-section.
- Every query on user-owned tables carries the authenticated `user_id` predicate in code.
- New integrations ship behind a settings flag and no-op cleanly when unconfigured.
- Settings access is lazy (`pydantic-settings` at call time); importing a module never
  requires an env var.

## Migrations

- One migration per PR, generated (`alembic revision --autogenerate`), never hand-edited
  after review starts. Regenerate after rebasing — do not renumber by hand.
- Migrations are hold-tier: agents write them, humans merge them.

## Memory

- `docs/solutions/` — grep before debugging anything familiar.
- `docs/decisions/` — read the relevant ADR before changing a decided area.
- `docs/plans/` — write a plan before multi-file work.
- After a non-obvious fix: solutions entry in the same PR. A rule that would have prevented
  the problem → amend this file in the same PR.

## Never

- Flip feature flags, edit env/secrets, or run migrations against production.
- Merge outside the policy in `docs/autonomy-runbook.md`.
- Touch payments/auth beyond the picked item's written spec.
