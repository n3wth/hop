# ENOSPC disk space exhaustion during Vitest suite execution and cron sweep audit

## Problem

During the 3-hour scheduled cron sweep, `npm run check` failed with 71 Vitest test suite failures displaying:
`Error: ENOSPC: no space left on device, open '/var/folders/p_/_zcx6z4d5vgbp06b3vd7xv500000gn/T/...'`

Checking filesystem disk space with `df -h` revealed `/System/Volumes/Data` was at **100% capacity** with only ~120Mi available.

## Root Cause

An audit of `/var/folders` using `du -sh /var/folders/*/*/*` identified a 16GB temporary directory at `/var/folders/p_/_zcx6z4d5vgbp06b3vd7xv500000gn/X/com.google.Chrome.code_sign_clone`, generated by background macOS Chrome auto-update code-signing processes. Combined with accumulated `_npx` cache items, the temporary storage location used by Vitest for SSR bundle transforms ran out of space (`ENOSPC`).

## Solution

1. Removed the stale Chrome code signing clone directory in `/var/folders/.../X/` and cleaned temporary npx caches.
2. Verified disk capacity restored to 2.3Gi+ available.
3. Re-ran `npm run check` — all 121 test files (1,406 unit/integration tests), ESLint, typecheck, and migration sequence checks passed cleanly.
4. Re-ran `npm run build` — Next.js 16.2.9 production build compiled successfully in 9.4s across 161 static/dynamic routes.
